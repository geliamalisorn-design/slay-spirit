# Подключение Spirit LLM Proxy

Backend использует Spirit Chat Completions для образовательного разбора свободного ответа игрока после отправки раунда. В текущем Spirit доступе `POST /v1/responses` возвращает 404, а документированный `POST /chat/completions` отвечает. Модель получает учебный контекст, выбранные факторы и ответ игрока (до 500 символов). Она не видит будущие цены и не управляет игровыми расчётами. Запрос отправляется только с backend; имя и email аккаунта в него не входят.

## Настройка

Локальный запуск `python server.py` загружает переменные из `.env` в корне проекта, не перезаписывая уже заданные переменные процесса. Docker Compose передаёт те же значения контейнеру backend через environment. Пример конфигурации:

```dotenv
SPIRIT_LLM_API_KEY=
SPIRIT_LLM_BASE_URL=https://llm-proxy.spirit.t-education.com/v1
SPIRIT_LLM_MODEL=openai/gpt-6-luna
SLAY_LLM_TIMEOUT=6
```

`SPIRIT_LLM_API_KEY` — Spirit API key (JWT). Не используйте ключи GitLab, Codex или OpenAI Platform. Храните ключ только в локальном `.env` либо в secret store среды запуска; `.env` исключён из Git. Не передавайте ключ в браузер или frontend. Доступная модель и квоты зависят от учётной записи Spirit; выберите модель с провайдерным префиксом из списка, доступного в Spirit.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `SPIRIT_LLM_API_KEY` | пусто | Серверный ключ Spirit; при отсутствии используется локальный fallback. |
| `SPIRIT_LLM_BASE_URL` | `https://llm-proxy.spirit.t-education.com/v1` | Базовый URL Spirit LLM Proxy. |
| `SPIRIT_LLM_MODEL` | `openai/gpt-6-luna` | Идентификатор модели с префиксом провайдера; должен быть доступен вашей учётной записи Spirit. |
| `SLAY_LLM_TIMEOUT` | `6` секунд | Тайм-аут запроса, ограничен диапазоном 1–10 секунд. |

## Stateless вызов и отказоустойчивость

Каждый раунд передаёт полный необходимый контекст одним Chat Completions запросом с `system` и `user` сообщениями. `SPIRIT_LLM_BASE_URL` может содержать суффикс `/v1`, но для Chat Completions backend нормализует адрес к корню host и вызывает `/chat/completions` ровно один раз, без перенаправлений. История диалога не хранится на стороне Spirit и не отправляется между раундами. Структурированный JSON проверяется backend по ограниченной схеме: факторы должны быть из разрешённого списка, а категории и длины текстов — допустимыми.

Отказ модели, ошибка сети, некорректный ответ, отсутствие ключа, превышение тайм-аута или лимита приложения приводят к локальному разбору по правилам. Игровой раунд завершается в любом случае. Сервер не пишет ключ, тело запроса или содержимое ответа в логи. Локальная история игры хранится приложением отдельно.

Backend ограничивает вызовы разбора до 10 попыток на аккаунт за скользящие 24 часа. После исчерпания этого лимита включается локальный fallback.

## Проверка

После отправки раунда с содержательным свободным ответом в блоке «Ваше обоснование» должен появиться статус **«Структурированный разбор LLM»**. При проблеме отображается **«Локальная проверка · LLM недоступна»**. Проверяйте ошибки без вывода `.env`, ключа, заголовков авторизации или содержимого запроса.

Документация Spirit: [использование LLM Proxy](https://docs.pages.t-education.com/docs/docs/ai/llm-proxy/usage/).
